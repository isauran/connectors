# BPMN + DMN + Wasman Durable Orchestration Example

Этот пример демонстрирует совместное использование:
1. **BPMN 2.0 движка** (`bpmn.Engine`) для оркестрации шагов процесса (обход графа, переходы, эксклюзивные шлюзы XOR).
2. **DMN вычислителя** (`bpmn.Evaluate`) для принятия бизнес-решений на основе таблиц правил (проверка кредитного лимита).
3. **Durable WASM SDK** (`wasman.Engine`) для выполнения изолированных шагов процесса (воркеров) в WASM с возможностью восстановления состояния памяти после сбоев (checkpoints).

## Сценарий процесса

1. Процесс начинается со `StartEvent`.
2. Первым шагом выполняется ServiceTask `check_rules`. Хост считывает входные переменные `age` (возраст) и `income` (доход), передает их в DMN-таблицу решений `decision.dmn` и вычисляет результат одобрения кредита (`approved` = `true` / `false`).
3. Эксклюзивный шлюз (XOR) проверяет значение `approved`:
   - Если `approved == true`, то выполняется ServiceTask `execute_payment` (выплата).
   - Если `approved == false`, то выполняется ServiceTask `log_rejection` (логирование отказа).
4. Оба ServiceTask запускаются как WASM-воркеры через SDK `wasman`.
5. Для демонстрации **Durable Execution** на первом шаге работы воркера симулируется падение (host crash). Воркер аварийно завершается, но его состояние памяти сохраняется на диске в виде чекпоинта.
6. Хост перехватывает сбой, сбрасывает флаг симуляции сбоя и повторно запускает шаг.
7. `wasman` автоматически загружает сохраненный снапшот, восстанавливает память воркера, и выполнение продолжается со следующего шага воркера (бизнес-логика), минуя повторную инициализацию переменных.
8. Процесс доходит до `EndEvent` и успешно завершается.

## Сборка и запуск

1. Скомпилируйте воркер в `.wasm` и запустите хост:
   ```bash
   make run
   ```
